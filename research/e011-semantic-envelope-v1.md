# E-011 — Transport-neutral inter-service semantics v1

**Status:** design artifact only; no transport, broker, service mesh, or persistence technology selected.  
**Gate:** implementation remains blocked on E-007 real-agent acceptance and completion of E-010 trust-boundary review. Research and deterministic model tests may proceed independently.

## 1. Separate semantics from wire protocol

The framework must define the observable semantics of a service call before comparing gRPC, Connect, JSON-RPC-over-HTTP, or another transport. MCP remains an agent-to-tool/resource protocol candidate; A2A remains an agent-to-agent task-collaboration candidate. Neither is assumed to be internal service RPC.

A transport adapter may encode this envelope differently, but it must preserve the required fields and outcomes.

## 2. Call envelope (logical fields)

| Field | Meaning | Trust rule |
|---|---|---|
| request_id | Unique identifier for one call attempt and response correlation | Generated by trusted caller runtime; not an idempotency key |
| parent_call_id | Parent call in causal chain | Diagnostic only |
| caller_service_id / callee_service_id | Authenticated service identities | Derived from authenticated peer identity, not payload assertion |
| operation_id / contract_version | Declared operation and pinned contract version | Resolved against trusted service registry/catalog |
| tenant_scope | Tenant routing/partition scope | Must be authorized against authenticated principal; never grants authority |
| principal | Authenticated principal acting for the call | Derived from verified identity/token or local trust channel |
| delegated_capability | Attenuated authority for one operation/resource/tenant | Signed or otherwise integrity-protected, audience-bound, expiry-bound, and non-amplifying |
| remaining_timeout | Remaining duration budget | Monotonic duration budget; subtract elapsed time at each hop |
| idempotency_key | Logical operation identity across retries | Required for effectful operations declared retryable |
| attempt | Attempt counter | Observability only; cannot authorize replay |
| trace_context | Causal trace propagation | Bounded and stripped of credentials/secrets |
| payload | Contract-validated input | Size-bounded; streaming/replay properties declared separately |

## 3. Outcome algebra

A boolean success/error is insufficient because the caller may lose a response after the callee commits.

- rejected_before_dispatch: callee was not invoked; retry policy may permit a new attempt.
- accepted_or_in_progress: callee durably admitted work; caller should query/reconcile by operation identity.
- completed: terminal outcome is known and available.
- failed_before_effect: callee guarantees no externally visible effect occurred.
- cancelled_and_stopped: callee confirms work stopped before an effect, or reports the committed effect separately.
- outcome_unknown_after_dispatch: invocation may have executed; caller must not blindly retry with a new idempotency key.

Timeout and connection reset after dispatch map to unknown outcome unless the adapter can prove non-delivery. Cancellation is a request to stop, not a distributed rollback.

## 4. Retry classification

| Condition | Safe default |
|---|---|
| Local validation failure before dispatch | Do not retry unchanged input |
| Authentication/authorization rejection | Do not retry until authority changes |
| Explicit rejection before dispatch | Retry only if policy allows and deadline remains |
| Accepted/in-progress | Poll/query same logical operation; do not create another |
| Known failure before effect | Retry only if operation policy allows |
| Response lost after dispatch | Reconcile using same idempotency key |
| Timeout with unknown commit state | Reconcile; never mint a new key automatically |
| Non-replayable stream partially consumed | Do not automatically retry |
| Cancellation requested but not acknowledged | Work remains in-flight; capacity is not released |

The callee must scope idempotency by authenticated tenant + operation + key and bind it to a versioned canonical semantic request hash. Same key/different hash is a conflict. A retry attempt has a new request_id but preserves the idempotency key.

## 5. Deadline and cancellation

- Caller computes a monotonic deadline locally.
- Before each hop, it sends remaining duration, not an absolute wall-clock timestamp.
- Receiver caps the received duration by its own configured maximum and starts a local monotonic timer.
- Remaining duration is reduced by elapsed time at every hop.
- Cancellation propagates downstream and is acknowledged only when the work has stopped or the callee reports that an irreversible effect already committed.
- A worker lease/capacity slot remains held until stop acknowledgement or lease expiry/recovery semantics make ownership safe.

## 6. Identity and capability attenuation

- Caller identity comes from authenticated transport peer or verified token.
- Tenant is a scope checked against that identity; it is not authority.
- Delegated capability binds issuer, subject, audience/callee, tenant, operation, resource constraints, expiry, and unique token ID.
- A downstream call may narrow authority but MUST NOT broaden operations, resources, tenants, or expiry.
- Replay protection and revocation semantics must be declared by the eventual credential adapter.
- Logs carry identifiers and decisions, never raw bearer tokens or capability material.

## 7. Streaming semantics

Every streaming operation declares whether request and response streams are replayable, resumable, or one-shot. Once a non-replayable request body has been consumed, transport retry must not replay it. A stream disconnect does not imply that server work stopped. Durable outputs need a retrievable operation/task result independent of a transient stream.

## 8. Minimum executable two-process experiment

After gates clear:
1. Start service A and service B as separate OS processes with separate state stores.
2. A invokes one declared B operation with authenticated service identity, tenant scope, attenuated capability, remaining deadline, and idempotency key.
3. B commits a local effect and idempotency result; inject response loss after commit.
4. A reconciles using the same key and obtains the original outcome without a duplicate effect.
5. A producer commits a local state change and versioned outbox event atomically; remote consumer deduplicates through an inbox transaction.
6. Inject failure before receive, after admission, before commit, after commit/before response, during stream, before consumer commit, and after consumer commit/before acknowledgement.
7. Verify restart recovery, duplicate delivery, tenant isolation, capability attenuation, bounded concurrency, and cancellation acknowledgement.

No in-process function call counts as evidence of inter-service behavior.

## 9. Decision gates

A transport candidate is eligible only after the same two-process semantic suite passes. Compare latency/throughput only after correctness. A storage/broker decision is separate from transport choice. Do not claim exactly-once network delivery or arbitrary external-effect atomicity.
